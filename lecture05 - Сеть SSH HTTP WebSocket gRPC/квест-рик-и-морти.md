# 🛸 Квест: «Рик и Морти. Портальная пушка пропала»

> Практика к лекции 5 (сеть: HTTP, заголовки, методы, cookie, редиректы,
> WebSocket, порты, TCP/UDP). Необязательное приключение для закрепления.

## Легенда

Рик снова всё испортил: **портальную пушку разобрали на 12 осколков кода** и
раскидали по измерениям одного сервера. Твоя задача, Морти, — пройти все
измерения, собрать осколки и собрать пушку обратно. В конце ты получишь
**личный флаг** вида `RICK{...}` — его и сдаёшь.

Осколки у каждого **свои** (привязаны к твоему логину). Обсуждать путь с
однокурсниками можно, а вот списать готовый ответ — нет: чужие осколки не
подойдут.

## Адрес

```
http://<IP_СЕРВЕРА>:8080
```

(конкретный IP даст преподаватель)

## Как начать

Зарегистрируйся своим GitHub-логином — получишь **личный токен**:

```bash
curl -s -X POST http://<IP>:8080/register \
     -H 'Content-Type: application/json' \
     -d '{"agent":"ТВОЙ-github-логин"}'
```

В ответе будет `token`. **Этот токен шли в заголовке `X-Portal-Token` в каждом
запросе.** В ответе также будет подсказка к этапу 1 — дальше сервер ведёт тебя
сам: каждый этап подсказывает, куда идти на следующем.

## Этапы (12 осколков)

Сервер подсказывает каждый шаг, но вот карта навыков, чтобы ты понимал, что
качаешь:

| #  | Что отрабатываешь                                           | Темы для повторения |
|----|-------------------------------------------------------------|---------------------|
| 0  | POST с JSON-телом, разобрать ответ                          | HTTP-методы, JSON, `curl -X POST -d` |
| 1  | читать **заголовки** ответа (`curl -v` / `-I`)              | HTTP-заголовки, `curl -v`/`-I` |
| 2  | `robots` и скрытые пути                                     | `robots.txt`, структура сайта |
| 3  | методы HTTP, `OPTIONS`, нестандартный метод                 | HTTP-методы, `OPTIONS`, заголовок `Allow`, 405 |
| 4  | **cookie** и **base64**                                     | HTTP cookie, `Set-Cookie`, base64 |
| 5  | виртуальные хосты (заголовок `Host`)                        | заголовок `Host`, virtual hosting |
| 6  | редиректы 3xx; `-L` против ручного прохода по шагам         | HTTP-редиректы 3xx, `Location`, `curl -L` |
| 7  | перебор параметра в цикле bash, проверка по HTTP-коду       | bash `for`/`seq`, HTTP-коды, `curl -w '%{http_code}'` |
| 8  | `Range`-запрос, частичный ответ 206                         | заголовок `Range`, 206 Partial Content |
| 9  | **WebSocket** (придётся написать маленький скрипт)          | WebSocket, `websocat`, Python `websockets` |
| 10 | **сканирование портов** и сырой **TCP** через `nc`          | TCP-порты, сканирование, `nmap`, `nc` |
| 11 | **UDP**-датаграмма (`nc -u`)                                | UDP vs TCP, `nc -u` |
| 12 | собрать все 12 осколков и собрать пушку (POST с JSON)       | JSON-массив, `curl -X POST` |

## Что понадобится из инструментов

`curl`, `nc` (netcat), `nmap` (или перебор портов циклом), `base64`, `bash`,
и для WebSocket — Python (`aiohttp`/`websockets`) или `websocat`.

## ⚠️ Правила (важно)

- **Сканировать и стучаться можно ТОЛЬКО по адресу `<IP>:8080` и портам в
  диапазоне `31000–31999` (TCP) этого же сервера.** Больше ничего и нигде не
  сканируй — ни другие хосты, ни другие диапазоны. Это условие задачи и правило
  вежливости в сети.
- Нагрузку держи разумной: этап с перебором — это сотни лёгких запросов, не
  надо слать миллионы.
- Токен личный — не делись им и не свети чужими осколками, всё равно не подойдут.
