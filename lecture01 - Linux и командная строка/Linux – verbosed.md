## Linux и командная строка.

Сегодня разберём, как устроена система, на которой крутится почти весь прод и весь ML-стек, и как с ней разговаривать из терминала – без мышки и без паники.

## **Сегодня пройдемся по этому плану:**

1. **Зачем Linux** – сервер почти всегда не Windows.
2. **Ядро и shell** – куда уходит команда, которую вы набрали.
3. **Дерево от** `/` – где я, куда иду, что лежит в корне.
4. **Файлы руками** – создать, открыть, запустить, удалить.
5. **inode и ссылки** – имя и данные это не одно и то же.
6. **Права** – кто и что может сделать с файлом и с папкой.
7. **Процессы** – PID, фон, как остановить.
8. **Потоки и конвейеры** – stdin / stdout / stderr, `|`, редиректы.
9. **Инструменты** – поиск, просмотр, окружение, пакеты.

## **Зачем нам Linux, если есть Windows.**

Вы, скорее всего, учитесь на Windows или macOS. А код обучается и крутится на сервере. Сервер почти всегда Linux.

Облака, GPU-машины, Docker, CUDA, PyTorch – родная среда там Unix-подобная. Всё скриптуется командами, а не кликами. Мышку на продовом сервере вы часто просто не получите: нет рабочего стола, есть shell.

Нейронки уже пишут команды лучше, чем мы с вами в первый день. Отказываться от них глупо. Пробел в другом: понять, *что* она написала, и суметь починить, когда упрётесь в `Permission denied` или в занятый порт.

За двенадцать занятий по инструментам цель не «стать хардкорным девопсом и писать баш весь день». Цель – структурно понимать Linux, контейнеры и путь приложения в прод. Сегодня – фундамент: терминал и устройство системы.

> **Linux** – это прежде всего ядро. Дистрибутив (Ubuntu, Debian, Mint, Arch) – ядро плюс набор программ, конфигов и установщик. Собрать «свой Linux» технически можно; на старте берите дружелюбный Ubuntu / Debian.

macOS – тоже Unix-подобная система. Если ноутбук уже Mac, отдельную Linux-машину для первой пары ставить не обязательно: команды те же по духу, пути чуть другие.

Как завести Linux, если его нет:

- простой путь – WSL на Windows или виртуалка (Parallels, VirtualBox, UTM);
- путь самурая – дешёвый VPS с Ubuntu и право её ломать.

Ломайте *свою* тачку. Боевой сервер, от которого зависят деньги, – не песочница.

`ssh` (secure shell) мы сегодня воспринимаем как «безопасный вход на другую машину». Порты, туннели и ключи разберём позже.

## **Куда уходит команда.**

Между вами и железом несколько слоёв.

```text
Приложения:  python · jupyter · git
      ↓
Shell – оболочка  (bash / zsh)
      ↓  системные вызовы (syscalls)
Ядро – kernel: процессы, память, файлы, драйверы
      ↓
Железо: CPU · RAM · диск · GPU · сеть
```

Верхние два этажа – userspace. Ядро – kernel. Вы пишете команду в оболочку. Оболочка просит ядро. Ядро трогает диск, память, сеть.

> **Shell (оболочка)** – программа, которая читает то, что вы набрали, и запускает другие программы. Часто это `bash` или `zsh`.

> **Ядро (kernel)** – часть ОС, которая одна имеет прямой доступ к железу и решает, кому можно память, диск и сеть.

Jupyter, Git, даже «просто Python» в итоге тоже ходят в shell и в ядро. На сервере сервис живёт не из ноутбука, а из процесса, который кто-то запустил в консоли. Ноутбук – для ресерча. Прод – для процесса.

## **Как устроена команда.**

Почти любая строка в терминале состоит из трёх частей: что делать, как делать, над чем.

```bash
ls -la /home/ivan
# ls  – list (список)
# -l  – long (длинный формат: права, владелец, размер)
# -a  – all (все, включая скрытые)
```

- `ls` – команда (list);
- `-la` – опции (флаги): как показать; склеились `-l` и `-a`;
- `/home/ivan` – аргумент: над чем работать.

Дальше в конспекте у каждой новой команды будет такая расшифровка, у флага – что значит буква.

Короткие опции можно склеивать: `-la` это `-l` и `-a`. Длинная форма часто выглядит как `--all` (тоже all). Почти у всего есть `--help` (help – помощь). Справка внутри системы: `man` (manual – руководство) `имя_команды`. Выход из мануала – клавиша `q` (quit).

Tab дополняет имя файла и команды. Стрелки вверх-вниз листают историю. Это не украшение: на длинных путях без Tab вы будете ошибаться в буквах.

## **Где я. Одно дерево от корня.**

Первая команда в незнакомой системе – «где я».

```bash
pwd    # print working directory – напечатай рабочий каталог
```

В Windows привычны диски `C:`, `D:`. Буквы `A:` и `B:` когда-то были дискетами. В Linux такой нарезки нет.

Всё – одно дерево. Корень называется `/`. Флешка, второй диск, сетевая шара монтируются *внутрь* этого дерева (часто `/media`, `/mnt`) и становятся обычными папками.

> **Абсолютный путь** – от корня, начинается с `/`. Пример: `/home/ivan/project`.

> **Относительный путь** – от того, где вы сейчас. Пример: `./example.py` или `src/app.py`.

> `.` – текущая папка. `..` – родитель. `~` – ваша домашняя (`/home/вы` на типичном Linux).

```bash
cd project/src    # change directory – смени каталог; путь относительный
cd /etc           # абсолютный путь от корня
cd ~              # домой; просто cd без аргумента – тоже домой
cd ..             # на уровень вверх
cd -              # в предыдущую папку
```

Ловушка: `./example.py` – это не «магическая текущая директория как тип файла». Это относительный путь к файлу `example.py` в текущей папке.

## **Что лежит в корне. FHS.**

Стандарт называют FHS – соглашение, *что где должно лежать* в Unix-подобных системах. От дистрибутива к дистрибутиву набор может чуть отличаться, идея одна.


| Путь             | Зачем                              |
| ---------------- | ---------------------------------- |
| `/bin`           | программы: `ls`, `cp`, `bash`      |
| `/etc`           | конфиги системы                    |
| `/home`          | домашние папки пользователей       |
| `/var`           | логи, кэши, очереди                |
| `/proc`          | процессы, «виртуальные» файлы ядра |
| `/usr`           | установленное ПО и библиотеки      |
| `/tmp`           | временные файлы                    |
| `/mnt`, `/media` | точки монтирования                 |


Двух разных `/home` быть не может: корень один.

```bash
cd /           # change directory – в корень
ls             # list – короткий список
ls -lah
# -l  – long
# -a  – all
# -h  – human-readable (размеры «по-человечески»: 4.0K, не 4096)
```

`ls` (list) показывает содержимое. Имена, которые начинаются с точки, по умолчанию скрыты – как «скрытые файлы» в проводнике.

`ls -lah` – удобная тройка на каждый день. `ls -a` без `-l` тоже покажет скрытые, но столбиком свойств не будет.

В `/home` у каждого пользователя своя папка. Зашли на сервер – попали в свою. Быстро домой: `cd ~`.

## **Кто я и что такое root.**

```bash
whoami    # who am I – под каким пользователем вы сейчас
w         # who – кто ещё сидит на этой машине (короткая родня who)
```

> **root** – суперпользователь. UID 0. Ему можно почти всё: менять чужие файлы, ставить пакеты, трогать сеть.

> **sudo** (superuser do) – «выполни эту команду от имени администратора». Не заклинание крутости. На работе за бессмысленный `sudo` на проде вам не поаплодируют.

```bash
sudo -i    # -i – login (интерактивная сессия root, как будто залогинились)
exit       # exit – выйти из этой сессии, вернуться к обычному пользователю
```

Обычному пользователю часто нельзя ставить системные пакеты, слушать низкие порты, полноценно крутить Docker. На своей виртуалке это как раз место учиться. Семь раз прочитали команду – один раз выполнили.

Группа `sudo` (или аналог) – люди, которым разрешили повышать права. Пользователи и группы как сущности нам понадобятся сразу в правах на файлы.

## **Создаём папку и файл.**

Работать лучше у себя дома, не в `/` и не в чужих системных каталогах. Иначе `Permission denied` – и это правильно.

```bash
cd ~                              # change directory – домой
mkdir -p ~/Desktop/devtools1
# mkdir  – make directory (сделай каталог)
# -p     – parents (создай родителей по пути; не ругайся, если уже есть)
cd ~/Desktop/devtools1
ls -lah                           # list: long, all, human-readable
```

> `mkdir` (make directory) – создать каталог. Флаг `-p` (parents) создаёт всю цепочку: несуществующих родителей достроит и не ругнётся, если папка уже есть.

Без `-p` команда `mkdir test/test1/test2` упадёт, если `test` ещё нет. С `-p` появится вся лестница сразу.

```bash
mkdir -p test/test1/test2
ls test
ls test/test1
rm -r test
# rm  – remove (удали)
# -r  – recursive (рекурсивно: каталог и всё внутри)
```

> `rm` (remove) – удалить. Для каталога нужен `-r` (recursive). Корзины нет. `rm -rf /` – `-f` это force (без вопросов) – историю, которую мы даже в шутку не набираем.

Пустой файл:

```bash
touch example1.py          # touch – «коснись»: создать пустой файл или обновить время
cat example1.py            # concatenate – склеить и вывести содержимое; файл пустой – и это нормально
```

> `touch` – создать пустой файл (или обновить время уже существующего).

> `cat` (concatenate) – вывести содержимое в терминал. Имя от «склеить несколько файлов в один поток».

Скопировать: `cp` (copy). Папку – `cp -r` (`-r` – recursive). Переместить или переименовать: `mv` (move). Переименование – это `mv` со старым и новым именем в той же папке.

```bash
mv err.log .err.log    # move – переместить / переименовать; стал скрытым: имя с точки
```

## **Редактор в терминале. Зачем, если есть VS Code.**

На сервере часто нет GUI. Нужно поправить одну строку – открываете файл в `vim` (Vi IMproved) или `nano` и правите.

Короткий маршрут по `vim` (его достаточно на старте):

1. `vim example1.py` – открыли.
2. Клавиша `i` – режим вставки. Внизу появится `INSERT`.
3. Пишете текст.
4. `Esc` – снова режим команд.
5. `:wq` и Enter – write + quit: записать и выйти.
6. Сломали всё и хотите уйти без сохранения: `:q!` – quit, force: выйти, отбросить правки.

Пока не нажали `i`, буквы – это команды, не текст. Компьютер «пищит» не со зла: вы не в режиме вставки.

`nano` мягче по подсказкам внизу экрана. Кто чем живёт – не религия. Важно уметь *выйти* и *сохранить*.

Напишем простой скрипт:

```python
a = 10

def foo():
    print(a ** 2)

foo()
```

Запуск:

```bash
which python3          # which – который: по какому пути shell найдёт python3
python3 example1.py    # -> 100
cat example1.py        # concatenate – снова посмотреть, уже не через vim
```

> `which` – по какому пути shell найдёт команду. Работает не только для Python: `which ls`, `which vim`.

Зачем гонять `.py` из консоли, если есть Jupyter? Любой сервис в проде – процесс из командной строки, не ячейка ноутбука. Ноутбук остаётся для исследования. Скрипт – для запуска.

## **Из чего состоит любой файл.**

Любой файл в Linux – даже папка, даже устройство – это две части.

1. **Данные** – содержимое: текст, картинка, бинарник программы. Могут быть пустыми, как после `touch`.
2. **Метаданные** – паспорт. Хранится отдельно от содержимого.

Когда вы создаёте файл, система выделяет место под данные *и* заводит индексную запись.

> **inode (ай-нод)** – паспорт файла: служебная запись файловой системы. Имя файла в ней не лежит.

Аналогия: наклейка на полке – имя. Номер стеллажа – inode. Книга на полке – блоки данных. В Python это похоже на имя переменной и объект: имя ссылается на объект, объект живёт отдельно.

Посмотреть номер:

```bash
ls -i example1.py      # -i – inode (покажи номер паспорта)
stat example1.py       # status – подробный паспорт файла
```



### **Что лежит в паспорте.**

В inode, среди прочего:

- размер в байтах;
- владелец (`UID`) и группа (`GID`) – числа, не «красивые имена»;
- права доступа – тройки `rwx`;
- временные метки: создание, изменение, последний доступ;
- ссылки на блоки данных на диске;
- счётчик жёстких ссылок – сколько имён указывают на этот inode.

Имена сопоставляются с `UID`/`GID` через `/etc/passwd` и `/etc/group`. Вы видите `ivan`, ядро считает число.

Имя лежит в **каталоге**. Каталог – список пар «имя → номер inode».

### **От имени до содержимого. Пять шагов.**

Представим: вы курьер, файл – посылка. Вы знаете только имя получателя, `file.txt`. Вот маршрут ядра, когда вы пишете:

```bash
cat /home/ivan/file.txt    # concatenate – выведи файл по абсолютному пути
```

Цепочка всегда одна: **имя → inode → блоки данных**. Скачков нет.

**Шаг 1. Ищем имя в каталогах.**

Ядро читает путь слева направо. Заходит в `/`, в таблице корня находит `home`, в `/home` находит `ivan`, в этой папке ищет строку `file.txt`.

Что лежит в каталоге? Обычная таблица: `file.txt` → номер inode, допустим `25678`.

Итог шага: имя больше не нужно. Есть число.

Чтобы вообще пройти по пути, на каждом каталоге нужен `x` (execute – «войти»). Без него ядро не дойдёт даже до поиска имени в конце.

**Шаг 2. Читаем inode.**

На диске есть таблица inode. Ядро берёт номер `25678`, идёт по адресу и вычитывает паспорт – маленькую структуру, обычно сотни байт, не мегабайты.

Внутри уже знакомое: размер, владелец и права, время. И главное – **массив номеров блоков**: где на диске лежат куски данных.

**Шаг 3. Ворота: права.**

Прежде чем трогать данные, ядро сравнивает UID/GID процесса `cat` с владельцем и группой из inode. Нет права `r` (read) на файл – сразу `Permission denied`. Блоки даже не читаются.

**Шаг 4. Карта сокровищ.**

Файл на диске редко лежит одним куском. В inode примерно полтора десятка указателей (упрощённо, как в классическом ext):

- **прямые** (штук двенадцать) – адреса первых блоков. Маленький файл, считанные килобайты, собирается сразу;
- **непрямые** – если файл большой, прямых адресов не хватает. Указатель ведёт на блок, который сам есть список адресов. Для совсем огромных файлов бывают двойные и тройные такие списки.

Ядро идёт по адресам, пока не наберёт весь размер из паспорта.

**Шаг 5. Склейка.**

Куски с разных мест диска склеиваются в памяти в один поток байтов и отдаются `cat`. На экране – уже целый текст.

Зачем так сложно? Inode всегда маленький, даже если файл 100 ГБ: внутри не данные, а адреса. А свободные ячейки диска можно заполнять вразброс – карта в inode потом собирает куски.

```text
имя в каталоге  →  inode (паспорт + адреса)  →  блоки данных
```

Жёсткая ссылка, к которой мы сейчас перейдём – это второе имя в какой-то таблице каталога с **тем же** номером inode. Курьер знает другого получателя, посылка на той же полке.

### **Почему это важно.**

Один inode может иметь несколько имён в разных папках. Это жёсткие ссылки: два имени – одни данные.

`rm` удаляет *имя из каталога*. Данные и inode исчезнут, когда счётчик ссылок станет 0 и никто больше не держит файл открытым.

`mv` внутри одной файловой системы обычно только меняет наклейку. Номер inode тот же – это можно проверить через `ls -i` до и после переименования.

## **Жёсткая ссылка и символьная.**

```bash
ln example1.py example_hard     # link – жёсткая ссылка: второе имя того же inode
ln -s example1.py example_soft  # -s – symbolic (символьная: хранит путь)
ls -li
# -l  – long
# -i  – inode
```

> **Жёсткая ссылка** – ещё одна этикетка на тот же inode. Переживает удаление «оригинального» имени, пока жив счётчик ссылок. На каталоги обычный пользователь так обычно не ссылается.

> **Символьная ссылка (symlink)** – маленький файл с путём к цели. Умеет указывать и на папки. Если цель удалить, ссылка «повиснет».

В `ls -l` symlink виден как тип `l` и стрелка на цель.

Симлинки часто ставят, чтобы коротко звать длинный путь к программе. Глубоко сегодня не копаем: идея «имя ≠ данные» важнее синтаксиса `ln`.

## **Права. Три буквы, три аудитории.**

Права – это кто *что* может сделать. Три действия и три аудитории.

Действия:

- `r` (read) – чтение;
- `w` (write) – запись;
- `x` (execute) – исполнение.

Аудитории:

- владелец файла (`u`);
- группа (`g`);
- все остальные (`o`).

Для **обычного файла**:

- `r` – прочитать содержимое;
- `w` – изменить содержимое;
- `x` – запустить как программу.

Для **каталога** смысл другой. Это отдельный атом, его путают чаще всего.

- `r` – увидеть список имён внутри (`ls`);
- `w` – создавать и удалять имена в этой папке (даже если сам файл «защищён»!);
- `x` – «войти» (`cd`) и обращаться к файлам по известному имени.

Ловушка: файл с правами `r--` в папке, где у вас есть `w` на каталог, вы всё равно можете *вычеркнуть из каталога*. Писать в содержимое – нет. Удалить имя – да. Каталог владеет именами.

## **Как читать строку** `ls -l`**.**

`ls` (list), `-l` (long) – одна строка на файл.

```bash
ls -l
# -> -rw-r--r--  1 root root 1234 Jun 10 12:00 myfile.txt
```

Разбор слева направо:


| Кусок         | Смысл                                                                   |
| ------------- | ----------------------------------------------------------------------- |
| первый символ | тип: `-` файл, `d` каталог, `l` ссылка; ещё бывают `b`/`c` – устройства |
| следующие 9   | `rwx` владельца, группы, остальных                                      |
| число         | сколько жёстких ссылок                                                  |
| два имени     | владелец и группа                                                       |
| число         | размер в байтах (без `-h`)                                              |
| дата          | время                                                                   |
| хвост         | имя                                                                     |


Пример `-rwxr-xr--`: владелец может всё, группа читать и исполнять, остальные только читать.

Числовой счёт `r=4`, `w=2`, `x=1`. Тройка `rwx` это 7. Запись `chmod 640` значит: владельцу 6 (`rw-`), группе 4 (`r--`), остальным 0 (`---`).

Полный доступ всем – `777`. Для секрета «только я читаю и пишу» часто `600`. Для скрипта «я меняю, остальные исполняют» часто `755`.

## **Как ядро решает, можно или нет.**

Процесс выполняется от имени пользователя: его `UID` и список групп. Открываете файл – ядро проверяет по шагам.

1. Если `UID` 0 (`root`) – в классической модели доступ есть (пока сверху не повешена другая политика).
2. Если вы владелец файла – смотрит первую тройку.
3. Если ваша группа совпала с группой файла – среднюю тройку.
4. Иначе – последнюю тройку, «остальные».

Это называется DAC: дискреционный доступ, «права на самом файле». Поверх могут быть SELinux или AppArmor – дополнительные ярлыки и политики. Они умеют отказать даже root, если правило запрещает. Для первой пары достаточно знать: классические `rwx` – основа, не вся вселенная.

Специальные биты – необязательно, но встречаются в жизни:

- **setuid** на исполняемом файле – программа стартует от имени владельца файла. Пример: `passwd` с setuid root, чтобы записать пароль в защищённый `/etc/shadow`;
- **setgid** – то же для группы;
- **sticky bit** на каталоге – удалять файл внутри может владелец файла (так устроен `/tmp`: вы не снесёте чужие временные файлы).

## **Меняем права:** `chmod`**. Запуск** `./файл`**.**

```bash
ls -l example1.py          # list, long
chmod +x example1.py
# chmod  – change mode (смени режим доступа)
# +x     – добавить execute (исполнение) всем трём классам
ls -l example1.py
```

> `chmod` (change mode) – сменить биты доступа.

`chmod +x` добавляет исполнение *всем трём* классам. Точнее: `chmod u+x` – `u` это user (только владелец). Числами – как договаривались: `chmod 755 example1.py`.

Сменить владельца: `chown` (change owner) `пользователь:группа файл` (часто нужен `sudo`).

Важная развилка с запуском.

```bash
python3 example1.py    # работает: исполняется python3, файл ему скармливают как текст
./example1.py          # shell сам пытается запустить файл → нужен x, и желательно shebang
```

Пока нет `x`, `./example1.py` даст `Permission denied`. Это не противоречие: в первом случае вы запускаете интерпретатор, во втором – сам файл как программу.

> **shebang** – первая строка `#!путь`. Shell читает её и понимает, каким интерпретатором кормить файл.

```python
#!/usr/bin/env python3
```

или жёстко `/usr/bin/python3`. `env` ищет `python3` в `PATH` – удобнее, если питонов несколько.

Тот же приём для shell-скрипта:

```bash
# файл qwe.sh
#!/bin/sh
echo hello-dev-tools    # echo – выведи строку обратно в stdout
```

```bash
chmod +x qwe.sh         # change mode, + execute
./qwe.sh                # -> hello-dev-tools
```

`.sh` – обычный текст в синтаксисе shell: те же `echo`, `cd`, `ls`, которые вы набираете руками. Так собирают маленькие джобы.

## **Процесс, PID, сигналы.**

Каждая запущенная программа – процесс. У него есть номер.

> **PID** – идентификатор процесса. Один и тот же файл можно запустить несколько раз – будет несколько PID.

Процессы образуют дерево: у каждого есть родитель. На современном Linux в корне дерева обычно `systemd` с PID 1.

```bash
sleep 30        # sleep – поспи N секунд; заберёт терминал; прервать – Ctrl+C
sleep 300 &     # & – фон; сразу вернёт PID
ps aux          # process status: таблица процессов
# a  – all (все пользователи)
# u  – user-oriented (колонки под пользователя: кто, CPU, память)
# x  – процессы без терминала тоже показать
ps aux | grep sleep
# grep  – global regular expression print: найди строки по шаблону
```

> **Конвейер** `|` – stdout левой команды становится stdin правой. Промежуточный файл не создаётся, данные текут через память.

`grep` (global regular expression print) ищет строки с подстрокой. Склеили: «все процессы, потом только те строки, где sleep».

`top` / `htop` / `btop` – диспетчер задач в реальном времени (top of processes). Сегодня достаточно знать, что они есть.

Остановить процесс:

```bash
kill 4821       # kill – пошли сигнал; по умолчанию SIGTERM
kill -9 4821    # -9 – номер сигнала SIGKILL (принудительно)
```


| Сигнал  | Как           | Смысл                                     |
| ------- | ------------- | ----------------------------------------- |
| SIGINT  | Ctrl+C        | прервать текущую команду в этом терминале |
| SIGTERM | `kill PID`    | мягкая просьба                            |
| SIGKILL | `kill -9 PID` | жёстко, без уборки                        |


Сервис на порту «не умирает» после закрытия вкладки – ищите PID через `ps aux | grep ...` и решайте, какой сигнал уместен. LLM посреди генерации: SIGTERM даст дописать, SIGKILL оборвёт на полуслове.

Ctrl+D закрывает stdin (часто закрывает сам shell). Ctrl+Z приостанавливает задачу – про `jobs` (список задач) / `fg` (foreground) / `bg` (background) поговорим в другой раз, если понадобится.

Зачем `sleep` в принципе? В скрипте: проверил диск, уснул на час, проверил снова. Самая глупая и понятная джоба.

## **Три потока. Куда девается вывод.**

У каждого процесса три стандартных потока.


| Номер | Имя    | Обычная жизнь     |
| ----- | ------ | ----------------- |
| 0     | stdin  | ввод (клавиатура) |
| 1     | stdout | обычный вывод     |
| 2     | stderr | ошибки            |


Их можно перенаправить в файл или склеить конвейером.

```bash
ls -lah > log.txt                 # list long/all/human-readable; stdout в файл (перезапись)
echo 'I am engineer' >> log.txt   # echo – выведи; >> дописать в конец
cat log.txt                       # concatenate – показать файл
```

Ловушка: `>` уничтожает прежнее содержимое. Обратной кнопки нет. `>>` дописывает.

```bash
cat not_exist              # ошибка на экран – это stderr
cat not_exist 2> err.log   # экран тихий, текст ошибки в файле
./qwe.sh 1> out.log        # обычный вывод в файл
```

Если ошибки не было, файл для `2>` будет пустым – и это успех.

Зачем складывать ошибки в файл? Логи в проде – единственный способ понять, что сломалось ночью. Консоль прокрутили – портянки больше нет. Сбор логов в файл сегодня – разминка; стеки вроде «куда пишут настоящие сервисы» будут позже.

Конвейер по шагам:

```text
cat app.log     →  все строки
     |
grep ERROR      →  только ERROR
     |
wc -l           →  сколько таких строк
```

> `wc` (word count) – посчитать. `wc -l` (`-l` – lines) считает строки, не «туалет».

```bash
cat access.log | grep 404 | wc -l
# concatenate | найти строки 404 | word count, lines
```

Ввод из файла: `cmd < in.txt` (stdin берётся из файла, не с клавиатуры).

## **Смотрим файл, не открывая редактор.**

```bash
cat app.py           # concatenate – весь файл, если короткий
less huge.log        # less – листать постранично (антипод more); выход q (quit)
head -n 20 app.log   # head – начало; -n – number (сколько строк)

```

Для живого лога `tail -f` (follow) незаменим.

## **Поиск:  строки и файлы.**

`grep` (global regular expression print) ищет **строки внутри файлов**. `find` ищет **сами файлы** в дереве.

```bash
grep "error" app.log
grep -in "TODO" *.py
# -i  – ignore case (без регистра)
# -n  – number (номера строк)
grep -v "DEBUG" app.log
# -v  – invert (все строки, кроме совпадения)
```

```bash
find . -name '*.py'
# find   – найди файлы
# .      – начать от текущей папки
# -name  – по имени (маска)
find . -type d         # -type d – directory (только каталоги); -type f – file
find . -size +1M       # -size – размер; + значит «больше»
```

Точка в `find .` – «начни отсюда». Маска `*.py` значит «префикс любой, конец `.py`». Скрытый `.r.log` тоже найдётся по `*.log`.

На слайдах ещё связка «find нашёл файлы, grep ищет внутри» – к этому вернёмся, когда привыкнем к `|`. Не обязательно запомнить `xargs` с первой пары.

## **Переменные окружения и PATH.**

У сессии терминала есть набор переменных: ключ и значение.

```bash
echo $USER              # echo – выведи значение переменной USER
echo $HOME
echo $PATH
env                     # environment – все переменные окружения сразу
```

```bash
export BOBA123=123      # export – отдай переменную дочерним процессам этой сессии
echo $BOBA123
```

Откроете **новое** окно терминала – `BOBA123` там нет. `export` в текущей сессии не делает переменную вечной. Постоянство – в файлах вроде `~/.bashrc` (выполняется при старте bash): alias, `export`, дописывание PATH. Сегодня достаточно идеи.

> **PATH** – список каталогов через двоеточие. Когда вы пишете `python3`, shell идёт по списку слева направо и берёт **первое** совпадение.

Поэтому `which python3` показывает не «единственный Python во вселенной», а тот, кто выиграл гонку по PATH. Несколько версий на машине – обычное дело.

Дописать каталог вперёд (только на эту сессию):

```bash
export PATH="/новый/путь:$PATH"
```

Секреты, токены, ключи API в код и в git не кладут. Файл `.env` в корне проекта – обычное место для `TOKEN=...`. В git его не коммитят. В коде читают окружение, а не строку-пароль в кавычках. Обвязку на Python (`dotenv`, менеджеры пакетов вроде `uv`) разберём позже. Правило унесите сегодня: креды – не часть исходника.

## **Пакеты системы и пакеты Python.**

Программы ОС ставят из репозитория, не с случайных сайтов. На Ubuntu / Debian это `apt` (advanced package tool).

```bash
sudo apt update            # superuser do; update – обновить индекс пакетов
sudo apt install htop      # install – поставить пакет (htop – интерактивный top)
apt search postgres        # search – найти пакет по имени
```

`apt update` обновляет *список* пакетов, не все программы сразу. `pip` / conda ставят библиотеки Python в своё окружение. Это другой этаж: `htop` – системная утилита, `pandas` – не через `apt`, если вы живёте в виртуальном окружении проекта.

На Fedora похожий смысл у `dnf`, на macOS часто `brew` (Homebrew).

## **sed и awk – одним взглядом.**

Оба читают поток построчно. Правило разделения:

- `sed` (stream editor) – про строки и замены;
- `awk` (имена авторов Aho, Weinberger, Kernighan) – про поля (колонки) и простую арифметику.

```bash
sed 's/foo/bar/g' f     # s – substitute (замени); g – global (все вхождения в строке)
awk '{print $1}' f      # напечатать первое поле
```

`$1`, `$2` – поля текущей строки, `$0` – строка целиком. На первой паре достаточно узнать, что такие пилы существуют. Конвейер `grep | wc` вы уже умеете; `awk` – сосед по мастерской.

## **Горячие клавиши и частые ошибки.**


| VКлавиша | Зачем                              |
| -------- | ---------------------------------- |
| Tab      | дополнить имя                      |
| Ctrl+R   | поиск по истории                   |
| Ctrl+C   | прервать команду                   |
| Ctrl+D   | конец ввода / часто выход из shell |
| Ctrl+L   | очистить экран                     |
| q        | выйти из `less` / `man`            |


Сообщения, которые вы увидите в первый же день:

- `command not found` – опечатка или пакет не установлен, проверьте `which`;
- `No such file or directory` – не тот путь, сделайте `pwd` и `ls`, жмите Tab;
- `Permission denied` – смотрите `ls -l`, дальше `chmod` или `sudo` осмысленно;
- «терминал завис» – часто команда ждёт ввод: Ctrl+C или Ctrl+D.
