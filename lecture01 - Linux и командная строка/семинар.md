# Семинар к Лекции 1. Linux и командная строка

Это конспект для практики в терминале. Цель — чтобы вы перестали бояться чёрного
экрана и своими руками прошли путь от «где я нахожусь» до конвейера из нескольких
команд. Все команды ниже можно (и нужно) повторять у себя: подойдёт любой
Linux-подобный shell — WSL, macOS, виртуалка или `ssh` на учебный сервер.

## Что понадобится

- Терминал с bash или zsh: команда `echo $SHELL` должна показать `/bin/bash` или
  `/bin/zsh`.
- Чистая рабочая папка, например `~/demo` — будем начинать с чистого листа.
- Установленные `grep`, `find`, `sed`, `awk`, `htop` (что-то из этого при
  необходимости поставим по ходу).
- Три спасательных сочетания на случай, если вы «застряли» в программе: `q` —
  выход из `less`/`man`, `Ctrl+C` — прервать команду, `Ctrl+D` — конец ввода.

## Зачем нам терминал

Обычно библиотеку ставят или скрипт запускают кнопкой в IDE. Но ваш код будет
жить не на ноутбуке, а на сервере с GPU, куда вы зайдёте по `ssh`. Там нет мышки
и окошек — только терминал. Поэтому учимся в нём жить.

Терминал — это просто способ давать команды оболочке (shell), которая переводит
их в системные вызовы к ядру. Держите в голове четыре слоя:
**вы → shell → ядро → железо**.

## Где я и что вокруг: навигация

Первая команда в незнакомой системе — всегда «где я»:

```bash
pwd                 # print working directory — где я сейчас
```
Ответ — абсолютный путь от корня `/`.

```bash
ls                  # что в текущей папке
ls -l               # подробно: права, владелец, размер, дата
ls -la              # ещё и скрытые файлы (те, что с точки)
```
Файлы, начинающиеся с точки (`.bashrc`, `.git`) — «скрытые», их показывает
только `-a`. Это не защита, а соглашение.

```bash
cd /                # перейти в корень
ls                  # увидим /etc /home /var /usr /proc ...
cd ~                # вернуться домой (~ = /home/<вы>)
cd ..               # на уровень вверх
cd -                # в предыдущую папку
```
Обратите внимание на дерево файловой системы: `/` — корень, всё растёт из него;
никакого «диска C:» здесь нет. Попробуйте сами выполнить `ls /etc` и `ls /home`.

**Лайфхак, который экономит нервы:** наберите `cd Doc` и нажмите **Tab** —
оболочка допишет `Documents/`. Автодополнение по Tab — самый важный навык вечера.

## Файлы и папки: создаём, копируем, удаляем

```bash
mkdir ~/demo && cd ~/demo
mkdir -p project/src project/data     # -p создаёт вложенные сразу
touch project/src/model.py            # пустой файл
echo "print('hello')" > project/src/model.py
cat project/src/model.py              # вывести содержимое
```
Здесь `>` перенаправил вывод `echo` в файл (подробно про это ниже, в разделе про
редиректы). `cat` печатает файл в терминал.

```bash
cp project/src/model.py project/src/model_backup.py
mv project/src/model_backup.py project/src/old.py   # mv = переименовать/переместить
ls -R project                                       # рекурсивно всё дерево
```
`mv` — это и «переименовать», и «переместить»; в Linux это одна операция
(меняется запись имени в каталоге, сам inode не трогается).

Удаление — и сразу про опасность:
```bash
rm project/src/old.py
rm -r project/data        # -r для папки
```
> **Осторожно:** `rm -rf /` или `rm -rf ~` уничтожает всё без вопросов и **без
> корзины**. В Linux удаление окончательно. Всегда перечитывайте путь перед
> `rm -rf`.

## Права доступа и процессы

### Права
```bash
ls -l project/src/model.py
# -rw-r--r-- 1 student student  16 ... model.py
```
Разберём строку `-rw-r--r--` по буквам:
- первый символ `-` — тип (файл; `d` был бы каталог);
- `rw-` — права **владельца** (u): чтение, запись, нет исполнения;
- `r--` — права **группы** (g);
- `r--` — права **остальных** (o).

```bash
chmod +x project/src/model.py     # сделать исполняемым
ls -l project/src/model.py        # теперь -rwxr-xr-x
chmod 640 project/src/model.py    # цифрами: rw- r-- ---
ls -l project/src/model.py
```
Цифры — это сумма битов `r=4, w=2, x=1`. `7 = rwx`, `6 = rw-`, `4 = r--`.
`chmod 640` = владелец `rw-`, группа `r--`, остальные — ничего.

```bash
sudo whoami        # root
```
`sudo` выполняет команду от имени администратора (root). Нужен, чтобы ставить
пакеты или править `/etc`. Правило: без нужды не `sudo`.

### Процессы
```bash
sleep 300 &        # запустить в фоне, вернёт [1] 12345 — это PID
jobs               # что работает в фоне
ps aux | grep sleep
```
Каждая программа — процесс со своим **PID**. `&` запустил её в фоне, не блокируя
терминал.

```bash
kill 12345         # вежливо попросить завершиться (SIGTERM); подставьте свой PID
kill -9 12345      # если не слушается — убить принудительно (SIGKILL)
```
Ещё два способа управлять живой командой с клавиатуры: `Ctrl+C` на работающей
команде (`sleep 300` без `&`) — это сигнал SIGINT, «прервать». А `Ctrl+Z` —
«пауза», процесс уходит в фон приостановленным.

## Потоки, редиректы, конвейеры — ключевой раздел

У любого процесса есть три потока: **stdin (0)** — вход, **stdout (1)** — вывод,
**stderr (2)** — ошибки. Представляйте процесс как коробку с тремя стрелками.

Сделаем данные для опытов:
```bash
printf "INFO ok\nERROR disk\nINFO ok\nERROR net\nDEBUG x\n" > app.log
cat app.log
```

Редиректы:
```bash
ls > files.txt          # stdout -> файл (перезапись)
ls >> files.txt         # >> дозапись в конец
cat notexist 2> err.log # stderr -> файл (ошибка ушла в файл, не на экран)
cat err.log
wc -l < app.log         # stdin <- файл: посчитать строки
```
`>` перезаписывает, `>>` дописывает. `2>` ловит именно ошибки (поток 2), а не
обычный вывод. Это разные потоки — их можно развести в разные файлы.

Теперь главный трюк вечера — **конвейер** `|`:
```bash
cat app.log | grep ERROR
cat app.log | grep ERROR | wc -l
```
`|` соединяет команды: stdout левой становится stdin правой. Мы собрали «покажи
строки с ERROR и посчитай их» из трёх крошечных программ. Это и есть философия
Unix: маленькие инструменты, соединённые в конвейер.

## Поиск и обработка текста

### grep — искать строки
```bash
grep "ERROR" app.log          # строки со словом ERROR
grep -i "error" app.log       # -i без учёта регистра
grep -n "ERROR" app.log       # -n с номерами строк
grep -c "INFO" app.log        # -c только количество
grep -r "print" ~/demo        # -r рекурсивно по всем файлам папки
```

### find — искать файлы
```bash
find ~/demo -name "*.py"      # по имени/маске
find ~/demo -type d           # только каталоги
find ~/demo -size +1M         # больше 1 МБ
```
Ключевая идея — «find про файлы, grep про строки», и их удобно связывать:
```bash
find ~/demo -name "*.py" | xargs grep "hello"
```
`find` нашёл файлы, а `grep` заглянул внутрь каждого. Вместе они отвечают на
вопрос «в каком питоновском файле есть слово hello».

### sed и awk — по-быстрому
```bash
sed 's/ERROR/CRITICAL/g' app.log     # заменить слово (потоком, файл не меняется)
awk '{print $1}' app.log             # первая колонка каждой строки
awk '$1=="ERROR"' app.log            # строки, где первое поле = ERROR
```
Запомнить просто — **sed про строки и замены**, **awk про поля (колонки)**. Для
разбора логов и CSV этого хватает на 90% случаев.

## Окружение и установка ПО

```bash
echo $HOME              # переменная окружения
echo $PATH              # где shell ищет команды
which python            # в какой из папок PATH нашлась команда
env | head              # все переменные (первые строки)
export GREETING="hi"    # задать свою переменную
echo $GREETING
```
Когда вы набираете `python`, shell перебирает папки из `PATH` по порядку и
запускает первую найденную. Постоянные настройки (свои переменные, alias, правки
PATH) кладут в `~/.bashrc` — он выполняется при каждом старте оболочки.

Установка пакета (если есть sudo и интернет):
```bash
sudo apt update         # обновить список пакетов
sudo apt install htop   # поставить программу
htop                    # интерактивный монитор процессов (выход — q)
```
`apt update` обновляет *список* пакетов, а не сами программы. И главное — `apt`
ставит **системные** пакеты; библиотеки Python ставятся через `pip`/`conda` в
виртуальном окружении. Это разные уровни, не путайте их (venv разберём на
отдельном занятии).

## Частые ошибки

- **«command not found»** — опечатка в имени либо программа не установлена /
  не в `PATH`. Проверьте `which <cmd>`.
- **«No such file or directory»** — не тот путь. Сделайте `pwd` и `ls`,
  посмотрите, где вы на самом деле. И вспомните про Tab-автодополнение.
- **«Permission denied»** — нет прав (`ls -l`, при необходимости `chmod`/`sudo`).
  Не лепите `sudo` ко всему — сначала поймите, почему запрещено.
- **Забыли `-r` у `cp`/`rm` для папки** — «omitting directory».
- **Снесли лишнее через `rm -rf`** — корзины нет; отсюда привычка перечитывать
  путь перед Enter.
- **Путаница `>` и `>>`** — первый перезаписывает файл целиком, второй дописывает.
- **«Терминал завис»** — на самом деле команда ждёт ввод (например, `cat` без
  аргументов читает stdin). Спасение: `Ctrl+C` или `Ctrl+D`.
- **`$PATH` против `PATH`** — при *чтении* значения нужен `$`, при *задании*
  (`export PATH=...`) — без `$` слева.
